# Evidence to storyboard

Establish the current deliverable and the reason to watch before choosing shots. Read the latest brief and decisions, not only the file labelled final. Preserve earlier versions as history and identify what superseded them.

## Build the source map

Use `source-map.md` for the fields and `../assets/paper-edit-template.json` as a small example. Separate observed content, transcript, document claim, client confirmation, proposal and unknown. Name a company, person, outcome or relationship only at the evidence level the source supports.

Inventory file IDs, locations, bytes and available checksums. An archive member can be available without being extracted. A name-and-size match is a candidate duplicate; verify hashes before removing a unique copy. Include remote IDs and a recovery path when the raw material is on another drive. A file listed remotely is not downloaded, and downloaded does not mean viewed.

Sample to find candidates, then review the selected ranges continuously with audio. Record source timecodes, event context, shot purpose and gaps. Do not infer identities from faces or turn folder labels into verified event descriptions.

## Make the causal chain

Write the core argument in a few connected sentences. Each beat should create a need for the next: question, context, action, evidence, consequence or next step. A capability film can move from a business need to a working approach, documented activity and a next step. A testimonial should follow a person's problem and response. A recap needs clear event context. These are choices, not mandatory templates.

For every proposed shot, state what it proves or lets the viewer understand. If neighbouring beats can be swapped with no loss of logic, check whether the sequence is merely a montage. Keep a quiet, longer shot when it carries the thought. Reserve fast cuts for actions that remain intelligible.

Record the outgoing movement, gaze, sound, shape or idea and the incoming connection. Do not add a generated travel shot just to fill time. A transition should explain a change in place, scale, time or meaning.

## Keep the deliverables related

Build the short version from the same central promise, with fewer supporting beats. Do not compress every long-film beat into a choppy sequence. Reframe the vertical version deliberately around faces, hands, proof and captions. A presentation should carry the same claims with references and readable still evidence; it need not reproduce every film shot.

Mark gaps explicitly: missing footage, unverified outcome, unclear permission, translation review or an unusable sentence. Offer a truthful substitute or a targeted request. Do not invent a completed project to make a capability claim feel stronger.

Deliver the source map, beat table, exact selected ranges, proposed narration or dialogue, transitions and unresolved decisions. Keep the approved story separate from new candidates.
